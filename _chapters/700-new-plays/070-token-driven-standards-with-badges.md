## Intent

Students accumulate badges indicating mastery of core and elective outcomes across course units, with their pattern of badges determining their final course grade.

## Problem

Conventional point-based grading in organic chemistry often obscures what students can actually do, discourages revision, and contributes to inequitable outcomes in a gatekeeper course. Students may fixate on partial credit rather than conceptual understanding, and one-time high-stakes exams leave little room for iterative improvement.

## Solution

The course uses a set of clearly defined learning outcomes grouped into "Parts" of the course, with some designated as Core and others as non-Core. Collaborative, multi-day take-home problem sets (THPS) link each problem to a single learning outcome and evaluate it on a pass/try-again basis. A token system lets students revise or reattempt THPS problems without penalty, converting "Try Again" work into passes. Badges are awarded when students pass the outcomes associated with a Part; the total number and combination of badges determines the final course grade.

## Applicability

Works well in content-heavy STEM courses where multi-step problem solving is central (e.g., organic chemistry, circuits, algorithms). Effective in medium-size courses where collaborative take-home assessments and individual follow-up are logistically manageable.

Tradeoffs/limitations: Requires significant upfront design of learning outcomes, THPS tasks, and badge thresholds. Instructors must track tokens, passes, and badges in a consistent way.

Not a good fit when: Courses where collaboration on major summative assessments is structurally impossible (e.g., tightly proctored licensure-style exams). Very large classes without support for managing token and badge tracking.

## How to Implement

1. Break the course into Parts, each with about six learning outcomes, marking some as Core (must-pass) and others as non-Core.
2. For each Part, create a multi-day collaborative problem set where each problem is explicitly tied to exactly one learning outcome, often using a claim–evidence–reasoning structure for responses.
3. Decide what constitutes "pass" for each outcome-aligned problem; if a student fails the Core or more than a set number of non-Core outcomes on a THPS, mark the entire set "Try Again" and return for revision.
4. Allocate each student a fixed number of tokens at the start of the term that they can spend to revise problems or reattempt learning checks. Specify rules such as one token per additional revision cycle on a THPS problem.
5. Define how many outcomes per Part must be passed to earn a badge and how many badges correspond to letter grades (e.g., a certain number of Part badges for an A).

## Examples

Each THPS contained six learning outcomes, with one designated as Core; passing the Core and a minimum number of non-Core outcomes earned a badge for that Part.

If a student missed the Core or more than one of the other five outcomes, the THPS was labeled "Try Again"; tokens allowed students to revise these responses and attempt to turn the THPS into a pass.

The course final grade was determined by the total number of badges across Parts, representing sustained mastery rather than cumulative points.
